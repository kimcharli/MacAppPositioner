# Remediation Plan — 2026-09-10

**Status:** Approved by @ckim on 2026-09-10. **Phase 0 complete** (2026-09-10) — see Outcome below. Phases 1–5 are queued and not yet approved for execution.

## Context

A full-repo audit on 2026-09-10 compared `TODO.md` against the actual implementation. The roadmap's status column proved unreliable: of the 14 items marked `[x]` in the 2026-02-27 code review section, 9 are genuinely complete, 3 are half-done, and 2 introduced new defects. More importantly, the roadmap omits the three highest-severity facts about the repo — the test suite does not run, `generate-config` emits invalid JSON, and `plan` disagrees with `apply`.

This plan sequences the remediation. It is ordered so that each phase is independently shippable and every phase after Phase 2 lands under test coverage.

## Root cause

D1, D4, D5 and the general untestability share one cause: **target window geometry is computed twice, in two places, under two different rules** — `CocoaProfileManager.positionApp()` and `CocoaProfileManager.createAppAction()`. These are parallel implementations that have already drifted. Fixes applied to one will keep missing the other.

The structural remedy (Phase 1) is a pure `LayoutEngine.resolve(...)` consumed by both paths, so that `applyProfile` becomes `execute(generatePlan(...))` and divergence becomes inexpressible rather than merely fixed.

## Scope rulings

- **Phase 0 is deliberately refactor-free.** Every item is a localized correctness fix. No signatures move, no files are added to the build. This keeps Phase 0 reviewable in isolation and safe to ship ahead of the Phase 1 restructure.
- **`generate-config` is rewritten to encode via `Codable`, not patched.** Deleting the stray comma from the string-concatenation template would fix this instance while leaving the whole class of bug in place. Encoding a `Config` value through `JSONEncoder` makes malformed output structurally impossible. This is a root-cause fix, ruled IN to Phase 0 despite being slightly larger than a patch.
- **The standalone `Tests/*.swift` scripts are NOT converted to XCTest in Phase 0** — deferred to Phase 2, which introduces `Package.swift`. Phase 0 only makes the existing runner point at files that exist.
- **`Tests/test_chrome_simple.swift`'s hardcoded `1329` is left alone** — dropped by design from Phase 0. That file asserts against the original author's specific display geometry and cannot pass on other hardware. It is superseded by Phase 2's fixture-based tests, not repaired.
- **`AppConstants.defaultWindowSize` is left in place** for Phase 0 even though `DEVELOPMENT.md:144` forbids hardcoded sizes. Resolving that contradiction requires the Phase 3 tiling decision.

## Phase 0 — Items to execute

### 0.1 — `generate-config` emits invalid JSON

- **File:** `MacAppPositioner/Shared/CocoaProfileManager.swift`, `generateConfigForCurrentSetup()` (lines 290–342).
- **Defect:** a trailing comma after the `layout` object (line 337) makes the output unparseable. Confirmed via `python3 -c "json.load(...)"` → `JSONDecodeError: Expecting value`. `CONFIGURATION.md:245` documents this command as the onboarding path, so the documented first-run flow produces a file `ConfigManager` refuses to decode.
- **Secondary defect:** the function assigns `role = .left` to every non-builtin monitor (line 307), contradicting `CocoaCoordinateManager.positionLabel(for:)` (line 246) which returns `.secondary` for the same monitor. A config generated by `generate-config` and a config written by `update <profile>` disagree.
- **Fix:** replace the string-concatenation template with construction of a `Config` value encoded by `JSONEncoder` (`.prettyPrinted`, `.sortedKeys`). Requires adding an explicit memberwise `init` to `AppLayoutEntry` in `ConfigManager.swift` (its custom `init(from decoder:)` suppresses the synthesized one). Use `.secondary` for non-builtin, non-workspace monitors. Emit normalized resolutions via `AppUtils.normalizeResolution`.
- **Third defect, found during execution (2026-09-10):** the `index == 0` workspace heuristic was **not** retained as originally planned. It is itself broken — when the built-in display sorts first in `NSScreen.screens` (as it does on the author's machine), `index == 0` is consumed by the `isBuiltIn` branch and *no monitor is ever labelled `workspace`*. `applyProfile` then aborts with "No workspace monitor found in profile". Verified: the old command emitted `[builtin, left, left]`. Replaced with "first non-builtin display becomes workspace", which emits `[builtin, workspace, secondary]`.
- **Parked, not fixed here:** `generate-config > config.json` still cannot be redirected, because `AppLogger.start()` and the CLI's `"Generated configuration for current setup:"` header both write to stdout ahead of the JSON. Fixing this requires routing diagnostics to stderr in the global `print()` override (`AppLogger.swift:111`), which is out of Phase 0's refactor-free scope. `CONFIGURATION.md:245` does not document redirection, and item 0.4 ships `config.example.json` as the supported template path. Tracked for Phase 3.

### 0.2 — Test runner points at files that do not exist

- **File:** `Scripts/test_all.sh`.
- **Defect:** all five hardcoded test filenames (lines 57–70) are absent; the real tests live in `Tests/` under different names. Additionally line 77 contains `${'='*50}`, Python syntax, which bash reports as `bad substitution`. Observed: 5/5 fail, exit 1. `DEVELOPMENT.md:81` advertises the suite as passing in ~10 seconds.
- **Fix:** repoint at the actual `Tests/*.swift` files; remove the Python-ism; drop the dead `if [ -f ... ]` duplicate blocks. Exclude `test_chrome_simple.swift` and any other test that requires the author's specific hardware, with an inline comment saying so and pointing at Phase 2.

### 0.3 — Redundant screen enumeration and unresolved builtin alias

- **File:** `MacAppPositioner/Shared/CocoaProfileManager.swift`, `generatePlan()` (line 128).
- **Defect:** calls `findWorkspaceMonitor(resolution:)` without `from: allMonitors`, causing a second `NSScreen` enumeration and config load. `applyProfile()` (line 193) passes it correctly — this is a straight inconsistency.
- **File:** `MacAppPositioner/Shared/CocoaCoordinateManager.swift`, `findWorkspaceMonitor()` (line 64).
- **Defect:** `detectProfile()` resolves the `"macbook"` / `"builtin"` resolution aliases (line 31) but `findWorkspaceMonitor` does not. A profile naming the built-in display as its workspace monitor detects successfully and then fails to apply.
- **Fix:** pass `from: allMonitors` in `generatePlan`; teach `findWorkspaceMonitor` the same alias resolution `detectProfile` already uses.

### 0.4 — No example config despite README instructing users to configure one

- **Files:** new `config.example.json`; `README.md` step 2; `docs/CONFIGURATION.md`.
- **Defect:** README Quick Start step 2 says "Configure your layouts in `config.json`" but no template ships with the repo, and `generate-config` (item 0.1) was until now producing invalid output.
- **Fix:** commit a `config.example.json` matching the "Complete Example" already in `CONFIGURATION.md:144`, and reference it from both documents. Verify it parses and that `ConfigManager` decodes it.

## Parked / deferred

- **Phases 1–5** (below) are planned but await explicit go-ahead from @ckim before execution. Tracked in `TODO.md` under the pointer to this document.
- **`positioning_strategy` — keep or delete?** Documented at `CONFIGURATION.md:138` but absent from the `AppSettings` model entirely. **@ckim must decide** whether Chrome needs a distinct strategy hook or whether the current `hasMovableWindow` PID selection has superseded it. Blocks Phase 3 item 12. Parked here until then.
- **Quadrant semantics — anchor or tile?** Today no code path ever resizes a window; `top_left` anchors a window at its existing size. README promises four zones. **@ckim must decide** whether to implement true tiling (behavior change for existing users) or correct the documentation. Blocks Phase 3 item 11.
- **`generate-config` stdout pollution.** Diagnostics share stdout with the JSON payload, so the output is copy-pasteable but not redirectable. Deferred to Phase 3 (see item 0.1). No decision needed — just sequencing.

## Later phases (not approved for execution)

- **Phase 1 — Unify plan and apply.** Extract pure `LayoutEngine.resolve`; make `createAppAction` and `positionApp` both consume it; make `applyProfile` execute `generatePlan`'s output. Fixes D1.
- **Phase 2 — Testability.** Add `Package.swift` (`MAPCore` / CLI / `MAPCoreTests`); introduce `ScreenProviding` and `WindowControlling` seams; port `Tests/*.swift` to XCTest with fixture screens.
- **Phase 3 — Honest config.** Real tiling via the already-present `size:` parameter; honor or delete `applications.positioning`; make `saveConfig` non-destructive (merge, don't re-encode); read or remove `@AppStorage("defaultProfile")`.
- **Phase 4 — Robustness.** Display identity via `CGDisplayCreateUUIDFromDisplayID`; harden `getBestWindow` (drop the `as!` force-cast, filter before accepting `kAXMainWindow`); move the apply loop off the main-thread `RunLoop.run(until:)` reentrancy pattern.
- **Phase 5 — Doc truth-up.** Remove the nonexistent `WindowManager` from `ARCHITECTURE.md:32` and `DEVELOPMENT.md:35`; reconcile Rule 3 with `AppConstants`; correct the three half-done `[x]` items in `TODO.md`.
